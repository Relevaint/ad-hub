# Helper scripts

Node standard library only, no packages to install. Node 20 or later. Each script's
header comment is its full usage. Run from anywhere; `--hub` defaults to this hub.

| Script | What it does | Used by |
| --- | --- | --- |
| `context.mjs --for <skill> --root <business repo> [--offer <slug>]` | Loads exactly the files a skill declares in its `reads`, from the business repo's `ads/` folder, with dates and age. Absent files are named with the skill that writes them and never block. Lists the business repo's other Markdown files by title so existing context can be found by meaning. Files older than 90 days (change with `--stale-days`) are flagged. | Every skill, at the start of a run |
| `freshness.mjs [files...] [--strict]` | Checks the `last-verified · ttl-days · refresh` header on dated reference files. Reports fresh, due soon, expired (with its refresh instruction) or broken. | The monthly refresh; the build gate (broken headers fail) |
| `route.mjs --goal "<request>"` / `--task <skill>` / `--list` | Points a request at a skill from the README task lookup and shows what that skill reads, writes and whether it can touch a live account. A plain word match: a fallback for platforms that do not list skills, not a replacement for reading the request. | Agents on Codex, Perplexity and the like |
| `workorder.mjs --for "<request>"` / `--id <work order>` / `--list` | Prints the summary of the work order for an output: what to load and each layer's name and what it builds, in order, from `../work-orders.json` ([staged work](../staged-work.md)). `--for` is a word match; with no clear winner it lists the closest and points at `start-here`. `--all` prints the full page, for a person reading or a session that cannot write a notes file. | Every skill, before producing anything |
| `workorder.mjs --id <work order> --layer <layer id> --notes <file>` | Opens one layer (or `whole`): prints its method, check and evidence once every layer before it has its section in the notes file (it refuses a never-opened layer whose section is already there), and on the first open appends an `opened:` line with the UTC time. Works after `--for` too. | Every layer, as it is reached |
| `workorder.mjs --id <work order> --layer <layer id> --repair <review number> --notes <file>` | Reopens a layer that was opened before, for the repair a review finding sent to it: prints its block again, appends a `## <layer id>: repair <N>` heading to the notes with a `reopened:` line under it (and the line to the ledger) on every call; the `Repair (review N):` paragraph goes directly under that heading. Prints the layer's check on its first line. Refuses on a layer never opened, on a layer that already holds a `Repair (review N):` paragraph before its reopen, and while an earlier layer reopened for the same review has no `Repair (review N):` paragraph. | After a review, at each layer a blocking finding names |
| `workorder.mjs --record <file>` | Checks a `## Layer record` table (or the one-line form in a reply) against its work order: every layer present, every pass with evidence and the evidence items its layer asks for, the state supported by the rows and naming every failed or unchecked layer, a review row whose findings were blocking or whose words changed after a fresh review, a copy pass with a `reworded` line, a pass that names a repair, blocking findings without the layers they sent back in brackets, a review row missing its four items once a review has run, a passing review whose `register:` is not `at register` or `n/a`, a cut not quoted, a repair paragraph with no `reopened:` line for its layer and review, a passed layer's section above its own `opened:` line, a missing ledger or a notes stamp the ledger lacks, a state saying "reviewed" over an unpassed review, and the notes file the record names (a heading and an `opened:` line per passed layer, the opens in order; a `reopened:` line and a repair paragraph for each layer the findings name, and no reopened layer as a plain pass; the loading layer names every Load first file and has an `Examples:` line). With `-`, a reply ending `Record: <path>` checks that file. | The agent at the end of a run; regression runs |
| `workorder.mjs --check` / `--write` / `--headings <file>` | Validates the map against the hub (owners are built skills, every file and heading a layer points at exists, every skill owns a work order, the generated pages are current); regenerates `work-orders/`; lists the anchors a layer may point at. | The build gate; anyone editing the map |
| `route.mjs --check` | Enforces the frontmatter rules every skill must meet (CONVENTIONS sections 2 and 3, README hard rules 5 and 6). The ledger is owned by transition: a write to it is declared as `ledger.md#<transition>`; the append-only `changes/` folder is declared `changes/#<label>` by each skill that writes entries. | The build gate |

Build gate, from the repo root: `npm test`. It runs the script tests against synthetic
fixtures in `test/fixtures/`, then runs the freshness and skill checks on the real hub and
checks that every regression case in `../regression/` is well formed, that the installer
(`install/adhub-skills.mjs`) and its hook work on a scratch copy of a business folder, and
that the work-order map is valid with its generated pages up to date.
